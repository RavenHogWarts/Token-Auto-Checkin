# 05 · 开发路线图

分阶段落地，每阶段可独立验收。目标是**先复刻已验证能力，再叠加三类场景的可配置化**。

## 里程碑总览

| 阶段 | 主题 | 产出 | 验收 |
| --- | --- | --- | --- |
| M0 | 工程脚手架 | WXT + TS + Vitest + ESLint 骨架，可加载空扩展 | `wxt dev` 能加载，popup 可开 |
| M1 | 领域层与存储 | `SiteProfile`/`CheckinResult` 类型、preset、storage 封装、旧配置迁移 | 迁移旧 `userSites` 单测通过 |
| M2 | 流水线 + 基础策略 | 编排器、`cookie`/`session-reuse`/`api`/`visit` 策略 | NewAPI 接口签到 + cookie 访问跑通 |
| M3 | OAuth 与 token 策略 | `oauth-linuxdo`（三站入口）、`token-storage` | Sub2API/ZenAPI 登录+签到跑通 |
| M4 | 三类场景可配置化 | `force-relogin`、`page-click`(选择器可配)、`manual-assist` | 场景 A/B/C 各有站点验证通过 |
| M5 | 人机验证与兜底 | 验证探测、前置窗口、兜底升级链、`needs-human` | 验证码站点能交人工并读结果 |
| M6 | UI 完整化 | 策略编辑面板、列表/拖拽/导入导出/定时、余额 | 交互对齐并超越参考实现 |
| M7 | 打磨与发布 | 跨浏览器构建、文档、图标、错误上报 | `wxt build` 产物可上架 |

## 阶段细节

### M0 · 脚手架
- 初始化 WXT 项目，配置 `wxt.config.ts`（权限、host_permissions、图标）。
- 接入 TypeScript strict、ESLint、Prettier、Vitest + chrome mock。
- 约定 `entrypoints/background.ts`、`entrypoints/popup/`。

### M1 · 领域层与存储
- 定义 `SiteProfile` / `CheckinResult` / 策略枚举（见 02 文档 Schema）。
- `domain/presets.ts`：newapi/sub2api/zenapi/custom 默认值。
- `services/storage.ts`：类型化读写；`domain/site-profile.ts` 的旧配置迁移（`type→preset`、`mode→checkin` 等）+ `legacyBackup`。
- **纯逻辑单测**：迁移、去重、preset 填充。

### M2 · 流水线 + 基础策略
- `core/tab-session.ts`（后台标签页会话）、`core/orchestrator.ts`（遍历/进度/取消/落盘）、`core/pipeline.ts`。
- `auth/cookie`、`auth/session-reuse`；`checkin/api`、`checkin/visit`。
- `page/read-login-state.ts`、`page/read-balance.ts`。
- 验收：NewAPI 站点接口签到成功；`custom` 站点 `cookie+visit` 访问成功并读余额。

### M3 · OAuth 与 token 策略
- `auth/oauth-linuxdo.ts`：整合参考实现三套 OAuth 入口（NewAPI `/api/oauth/*`、Sub2API `/api/v1/auth/oauth/linuxdo/start`、ZenAPI `/api/u/auth/linuxdo`）与「站点登录页通用入口」（自动切 `/login|/sign-in|/signin`、勾选协议、点 Linux.do、处理 `connect.linux.do` 授权页）。
- `auth/token-storage.ts` + `page/read-token.ts`（localStorage/sessionStorage 指定 key）。
- `services/auth-cache.ts`（7 天过期）。
- 验收：Sub2API（token/session 兜底）、ZenAPI（`user_token` + 标签页内执行）登录并签到成功。

### M4 · 三类场景可配置化（本项目重点）
- **场景 B** `auth/force-relogin.ts`：清 `authHeadersCache` + `chrome.cookies` 清站点 cookie（登出）+ 强制走 `oauth-linuxdo`，再签。提供 profile 开关 `auth.forceReloginEveryRun`。
- **场景 C** `checkin/page-click.ts`：`click.selectors` 用户选择器**优先于**内置文案；文案作兜底；沿用 `fetch/XHR` 劫持捕获响应。
- **场景 C 人工** `checkin/manual-assist.ts`：前台打开、`keepTabForManual`、轮询「已签/响应/用户确认」，超时给候选清单。
- 验收：分别配置一个「cookie 即签」「每次需重登」「需手点选择器」的站点，均按预期完成。

### M5 · 人机验证与兜底
- `services/human-verification.ts`：探测（文案 + 选择器）、命中 `needs-human`、按开关前置窗口；worker 回收后能恢复（避免强依赖 `setInterval` 内存态，用 alarms/storage）。
- `core/pipeline.ts` 的兜底升级链（api→page-click、401→relogin、CF→标签页内重试）。
- 验收：带 Turnstile 的站点能切前台交人工，用户完成后读到结果，状态显示 `needs-human`→`success`。

### M6 · UI 完整化
- 策略编辑面板（preset 下拉 + 高级折叠：auth/checkin 策略、选择器、强制重登、验证前置开关）。
- 列表渲染、拖拽排序、启用/禁用、增删改、导入导出、每日定时、余额展示、`needs-human` 的「去完成」入口。
- 验收：功能对齐参考实现，并新增策略配置与人工入口。

### M7 · 打磨与发布
- 跨浏览器构建（`wxt build` / `-b firefox`）、图标、README、隐私说明（数据仅存本地）。
- 关键路径日志与失败诊断（记录 `strategyUsed`、候选按钮）。
- 端到端回归：多站点混合批量签到。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| MV3 service worker 回收导致监控/长任务中断 | 状态落 storage；长轮询改 alarms；worker 启动时恢复运行态 |
| 站点前端改版导致选择器/文案失效 | 选择器可配置 + 文案兜底 + `manual-assist` 人工兜底 |
| linux.do OAuth 流程各站差异大 | 保留参考实现已验证的三套入口 + 通用登录页入口，作为独立策略隔离维护 |
| Cloudflare / 人机验证无法自动化 | 明确交人工（前置窗口），不追求全自动，`needs-human` 状态透明告知 |
| 强制重登清 cookie 影响用户其它标签页会话 | relogin 仅针对目标域名、在临时标签页内操作；文档提示该策略副作用 |
| 迁移旧配置字段缺失 | preset 默认值补齐 + `legacyBackup` 可回滚 |

## 验收总标准

1. 参考实现的全部现有能力在新版可复现（NewAPI/Sub2API/ZenAPI 接口签到、页面兜底、仅访问、余额、定时、导入导出）。
2. 三类场景可通过**配置**（非改代码）实现：cookie 访问即签 / 每次重登 / 手动点击（含选择器与人工兜底）。
3. 新增一类站点/策略无需改动流水线主干。
4. `tsc --noEmit` + `eslint` + `vitest run` + `wxt build` 全绿。
