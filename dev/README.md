# 公益站自动签到 Chrome 工具 — 方案文档

本目录是「公益站自动签到 Chrome 扩展」重构版的设计文档集合，仅包含**方案与设计**，不包含代码。参考实现位于 [`../reference/api-auto-chekin/`](../reference/api-auto-chekin/)。

## 背景

参考实现（`reference/api-auto-chekin`，MV3 + 原生 JS）已能覆盖 NewAPI / Sub2API / ZenAPI 三类站点的接口签到，并带有「页面按钮兜底」和「仅访问」模式。但存在三个尚未系统化解决的问题：

1. **部分站点需要退出后重新登录**才能签到（session 过期、cf_clearance 失效、必须走一次 OAuth）。
2. **部分站点只需打开网站（携带 cookie）即可自动签到**。
3. **部分站点的签到位置需要手动点击**（按钮选择器不固定，或存在人机验证）。

现有代码把这三类场景**硬编码**在一条固定流水线里（接口 → 页面兜底），难以扩展和配置。本方案的核心是把「签到方式」抽象为**可配置的站点策略（Strategy / Adapter）**。

## 一句话结论

推荐 **TypeScript + WXT（基于 Vite 的浏览器扩展框架）** 重写，用**声明式「站点档案（Site Profile）」+ 策略插件**替换现有硬编码流水线，把「cookie 访问 / 重新登录 / 手动点击」三类场景收敛为同一套可配置模型。详见 [03-技术栈选型.md](./03-技术栈选型.md)。
